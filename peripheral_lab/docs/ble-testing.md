# BLE 基础测试使用说明

目标：SiFli SDK v2.5.1、sf32lb52-lchspi-ulp、LVGL v9。此版已完成编译和主机模拟验证，尚未烧录验证实际无线连接。

## 页面与功能

首页进入 **Bluetooth → Open BLE tests**。四个页签独立操作，底部 STOP BLE / Done / Back 始终可用，边缘返回手势也会清理活动。

| 页签 | 功能 |
|---|---|
| Status | 协议栈就绪、本机地址/广播名、连接状态、协商 MTU、连接间隔、TX/RX PHY；开始广播、扫描、请求 1M/2M PHY |
| Scan | 10 秒主动扫描、最多 30 个设备；名称、地址及类型、RSSI、PHY；按地址+类型去重；选中后主动建立 GAP 连接 |
| Data | 手机向 RX 写入、订阅 TX 通知、发送挑战包、可选 RX 回显、收发计数和最近 RX 十六进制内容 |
| Pair | 配对、显示/确认数字、接受/拒绝、实际加密和绑定状态；停止后删除最后连接设备的绑定 |

默认传统可连接广播，广播名 `SiFli-Lab-xxxx`，包含测试服务 UUID。广播等待连接最多 60 秒；扫描 10 秒；主动连接设有超时。只使用一个连接，开始另一个活动前先 STOP。

主动扫描/连接用于 GAP 验证；**本版没有实现通用远端 GATT 服务浏览、读写界面**。GATT 数据验证以板子作为 Server、手机作为 Client 为主。最大属性数据固定 20 字节，兼容默认 MTU，不进行大包分片或吞吐压测。

## 手机连接及收发

1. 打开手机的 BLE GATT 调试工具（不是系统的蓝牙音箱配对页面）。
2. 板上点击 **Advertise**，扫描 `SiFli-Lab-xxxx` 后连接。
3. 打开下面的自定义服务，在 TX 上启用 Notify。
4. 向 RX 写入 1–20 字节；板上 Data 页面应显示 RX 字节数和内容。
5. 打开 **Toggle RX echo**，再写入一段数据，手机应收到同样的 TX 通知。
6. 点击 **Send challenge**，手机收到 12 字节数据后，将原始字节写回 RX，十秒内匹配才增加 `Verified round trips`。

| 项目 | UUID | 操作 |
|---|---|---|
| Service | `7bc10000-8a52-4c65-9c31-5349464c4901` | 自定义服务 |
| RX | `7bc10001-8a52-4c65-9c31-5349464c4901` | Write / Write Without Response，1–20 字节 |
| TX | `7bc10002-8a52-4c65-9c31-5349464c4901` | Notify；CCCD 写 `01 00` 开启 |
| Status | `7bc10003-8a52-4c65-9c31-5349464c4901` | Read，返回 `SiFli Lab BLE v1` |

注意“十六进制模式”与“文本模式”的区别：收到 `4C 41 42 31 ...` 后应按十六进制原样写回，不要发送这些字符的文本。挑战包布局为 `LAB1` + 32 位小端序号 + 前八字节 FNV-1a 32 位小端校验值；匹配整包并且当前正在等待，才判定回环通过。

`TX bytes` 表示 SDK 接受的发送字节，不表示手机应用已收到。通知缓冲区忙时显示错误并允许重试，不阻塞 UI，也不虚增 TX。接收到已匹配的挑战回送后不再次回显，避免与对端自动回显形成重复通知。

## 配对与绑定

连接后点击 Pair，或者由手机发起配对。Numeric Comparison 时在两端比较六位数字，再点 Accept；也可 Reject。请求最多等待 25 秒。需要输入本机键盘口令的配对方式暂不支持，会明确拒绝并提示从手机发起。

通过 connection manager 查询实际加密/绑定状态，不以普通连接成功代替安全连接。STOP 断开链路但保留绑定；重连时需重新开始广播。`Forget peer` 仅删除本次启动以来最后连接设备的绑定，需 STOP 后再连续点击两次；手机侧也要忘记此设备。不会调用全量删除绑定接口。

绑定存储复用 SDK NVDS/FlashDB，目标板已有 `ble` / `KVDB_BLE_REGION` 分区（板级 ptab offset 0x00DA4000、size 0x4000），本次未修改分区表。跨重启绑定恢复需要上板验收。

## 实现结构与生命周期

- `src/lab_ble.h`：命令、UI 快照及模型接口。
- `src/bluetooth/lab_ble_service.c`：SDK 接入、专用线程、32 项事件队列、连接/广播/扫描/配对生命周期。
- `src/bluetooth/lab_ble_model.c`：广播名称长度检查、设备去重/上限、挑战校验。
- `src/lab_ble_ui.c`：四页 UI、配对提示、设备选择与操作说明。

SDK 回调复制数据后返回，不调用 LVGL；UI 每 250 ms 读取互斥保护的快照。停止会使旧 UI 命令失效，清理扫描、广播、连接请求和连接；等完成事件后才允许启动新活动。关键事件队列溢出或清理超时会提示重启，不假装已经恢复。扫描报告过多时允许丢弃并显示计数。退出 BLE 页面不关闭整个蓝牙协议栈，只关闭测试相关的无线活动。

协议栈初始化与 UI 并行；BLE 不占用现有外设测试 worker。LCPU 镜像通过 `AddLCPU` 按板型生成，生成的 `src/lcpu_img.c` 不加入版本控制。经典蓝牙音频 profiles 仍未启用。

## 验证记录与上板清单

已通过：

- HCPU + LCPU 编译、链接；原 SDK 的 RWX/newlib 系统调用/FTAB 入口警告仍存在，本次没有新的 BLE 编译警告。
- 实际 LVGL 页面打开/返回、页签、命令按钮、配对页自动切换、停止与退出清理调用；当时 15 个外设页面回归（当前加入 PAN 后为 16 个，见接手记录）。
- 广播数据边界、名称截断、地址+类型去重、30 项列表上限、挑战序号/错误包验证。
- 使用真实 SDK 类型声明和生产状态机、模拟传输：旧命令取消、异步停止、未订阅禁止通知、发送背压、精确回环、迟到连接拒绝、配对人工确认、RX 长度和队列满处理。

上板仍需：手机发现/连接、Notify 和 RX 双向传输、配对确认/拒绝/重启恢复、1M/2M 协商、手机关闭蓝牙、连接中返回页面、反复扫描/断连及运行时内存检查。主机测试不验证 RF、真实 FlashDB 持久化或手机兼容性。
