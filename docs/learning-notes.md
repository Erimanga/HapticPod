# 嵌入式学习笔记

> 给第一次接触 MCU / RTOS / LVGL 的自己。这里只记录项目当前需要理解的概念，不追求教材式完整。

## 1. 整体关系

```text
HapticPod 应用代码
        │
        ├── LVGL（GUI）
        ├── 音频/文件/通信模块
        │
        ↓
    RT-Thread（RTOS）
        ↓
    SiFli SDK / HAL / 驱动
        ↓
 sf32lb52-lchspi-ulp 板级配置
        ↓
    SF32LB52 MCU
        ↓
      黄山派
```

## 2. MCU

MCU = Microcontroller Unit，微控制器。

可以把它理解成面向嵌入式设备的小型计算机芯片，通常集成 CPU、存储接口、GPIO、UART、I2C、SPI、定时器等外设控制能力。

本课程开发板主控属于 SF32LB52 系列。

## 3. 黄山派

黄山派是具体开发板。

“MCU”描述核心芯片，“开发板”则还包含屏幕、触摸、供电、接口和各种板载外设。

## 4. `sf32lb52-lchspi-ulp`

这是课程工程使用的板级配置名称。

它告诉 SDK：当前编译目标是哪一块具体板、使用什么硬件配置。

## 5. SDK

SDK = Software Development Kit。

SiFli SDK 是开发 SF32LB52 的软件工具和代码基础，提供构建系统、HAL、驱动、组件、示例等。

项目不是直接从裸寄存器开始写所有功能，而是大量调用 SDK 已经提供的能力。

## 6. RT-Thread

RT-Thread 是 RTOS（实时操作系统）。

现阶段把它理解成“管理 MCU 上多个任务的轻量操作系统”即可。

HapticPod 后续可能同时存在：

```text
UI 任务
音频任务
UART 通信任务
文件/存储任务
系统状态任务
```

学习重点：线程、消息/事件、延时、共享数据、避免阻塞。

## 7. LVGL

LVGL 是嵌入式 GUI 库。

它负责屏幕上的：

- 文本
- 按钮
- 列表
- 图片
- 进度条
- 布局
- 动画
- 触摸事件

课程基线使用 LVGL v9。

## 8. 编译

把 C/C++ 源代码转成 MCU 可以执行的固件。

目前只需要记住：

```text
源码 -> 编译/链接 -> 固件
```

“编译成功”只证明工程能生成产物，不证明实物功能正确。

## 9. 烧录

把编译生成的固件写入开发板的 Flash，让 MCU 下次启动时运行它。

```text
源码 -> 编译 -> 固件 -> 烧录 -> 开发板运行
```

## 10. 串口 / UART

UART 是很常见的串行通信方式。

初学阶段最重要的两个用途：

1. 看开发板日志；
2. 后续让黄山派和 FOC MCU 通信。

## 11. GPIO

GPIO = General Purpose Input/Output。

可作为普通数字输入或输出，例如：

- 读取按键；
- 控制 LED；
- 输出简单控制信号。

## 12. I2C

常用于连接传感器、编码器或控制芯片。

特点：通常两根信号线，可挂多个设备，每个设备通过地址区分。

## 13. SPI

高速同步串行接口。

显示屏、Flash、存储等场景经常使用。

## 14. 状态机

状态机用来回答：

> 系统现在处于什么状态？发生某个事件后应该去哪里？

例如播放器：

```text
STOPPED -> PLAYING -> PAUSED
     ^          |         |
     └----------┴---------┘
```

以后 UI 和播放逻辑不要各自偷偷维护一套互相矛盾的状态。

## 15. HapticPod 的统一输入层

计划把真实输入统一成：

```text
INPUT_CW
INPUT_CCW
INPUT_PRESS
INPUT_BACK
```

这样 UI 不关心输入来自：

- 临时按键；
- 机械编码器；
- BLDC 触觉旋钮；
- 其他输入设备。

这会显著降低后续联调难度。

## 16. 现在不需要掌握的内容

暂时不要因为看不懂而焦虑：

- Clarke / Park 变换
- SVPWM
- 电流环 PI
- PCB 高速设计
- 音频 Codec 细节
- 复杂 RTOS 调度理论

需要时再学。
