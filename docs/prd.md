# HapticPod 产品需求文档（PRD）

状态：草案 / 尚未立项确认

> 当前内容只是需求骨架。第 6 周立项前，应根据实际预研结果确认“必达”和“拓展”，不要把所有设想都承诺为必达。

## 1. 产品定义

HapticPod 是一个基于黄山派的嵌入式音乐交互终端，尝试用可编程触觉旋钮把“菜单、音量、进度”等数字状态转换成可以直接感受到的机械手感。

## 3. 核心使用闭环

候选流程：

```text
开机
 -> 进入音乐菜单
 -> 旋转选择歌曲/项目
 -> 按压确认
 -> 播放
 -> 调节音量/进度
 -> 屏幕 + 旋钮触觉反馈
 -> 暂停/返回/切歌
```

## 4. 必达需求（待立项确认）

### FR-001 启动与主界面

- 前置条件：设备正常上电；
- 输入：开机；
- 输出：显示 HapticPod 主界面；
- 失败行为：无法初始化时给出可观察错误状态；
- 验证：连续启动若干次，记录成功/失败。

### FR-002 菜单导航

- 输入：`INPUT_CW` / `INPUT_CCW`；
- 输出：选中项对应移动；
- 失败行为：异常输入不得造成状态越界；
- 验证：连续正反向操作并检查选中状态。

### FR-003 按压确认

- 输入：`INPUT_PRESS`；
- 输出：执行当前选中操作；
- 失败行为：重复输入不得造成不可解释的重复跳转；
- 验证：覆盖各主要页面状态。

### FR-005 可编程旋钮触觉

第一版建议只承诺一种或少量稳定效果，不要一开始承诺全部效果。

候选：

- 恒定阻尼；
- 虚拟卡点；
- 虚拟限位。

验证必须能够重复操作和描述。

### FR-006 黄山派与旋钮控制器通信

- 链路：UART（候选）；
- 输入事件：`+1 / -1 / PRESS` 或统一协议；
- 模式下发：菜单/音量/进度等触觉模式；
- 断连：应有明确行为，不冒充正常连接。

## 5. 拓展需求

以下功能不默认属于必达：

- 专辑封面 / ID3 元数据；
- 更复杂 LVGL 动画；
- 多种可调触觉曲线；
- LRA 整机震动；
- 3.5 mm 耳机输出；
- 电池供电；
- 转接 PCB；
- 3D 打印完整结构；
- CNC 外壳。

## 6. 非功能需求

不要只写“流畅/实时/稳定”，后续应改成可测量目标。

待定义指标：

- UI 输入响应延迟；
- 菜单连续操作漏触发率；
- UART 异常恢复；
- 持续运行稳定性；
- 内存占用/峰值；
- 音频播放时 UI 是否可正常响应。

## 7. 主要风险

| 风险 | 影响 | 预研方式 | 降级方案 |
|---|---|---|---|
| LVGL/音频并发导致卡顿 | 高 | 先做最小 UI + 音频测试 | 减少动画/简化音频功能 |
| FOC 旋钮控制难度高 | 高 | 独立桌面原型 | 先用普通编码器/按键保留 UI 闭环 |
| UART 联调问题 | 中 | 最小消息往返 | 简化协议 |
| 机械结构来不及 | 中 | 先 3D 打印 | 裸机/临时支架完成验收 |
| 耳机输出复杂 | 中 | 单独音频预研 | 使用课程已有可用音频输出路径 |
