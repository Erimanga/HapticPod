# 课程要求摘要

> 目的：把课程 PDF 中与项目开发直接相关的要求整理成便于随时查看的版本。本文不是课程原文替代品；若有冲突，以教师发布的最新材料为准。

## 1. 课程最终要做什么

课程要求以黄山派参与的系统完成一款嵌入式产品。

最终需要做到：

- 有真实可运行的使用闭环；
- 工程能够复现；
- 有完整研发过程材料；
- 能说明自己的需求、设计、实现和验证；
- 能在真实黄山派上完成核心功能验收。

课程不要求必须自研 PCB、结构件或量产方案。

来源：课程指导手册第 1 页。

## 2. 技术基线

课程示例代码的技术基线：

- SiFli SDK v2.5.1
- RT-Thread
- LVGL v9
- Board：`sf32lb52-lchspi-ulp`

有图形界面的项目使用 LVGL。

其他版本/技术不是绝对禁止，但需要说明采用理由，并提供适配与复现方法。

来源：课程指导手册第 4 页。

## 3. 黄山派必须真正参与产品

可以使用：

- 手机
- 电脑
- 云端
- 外接模块
- 其他控制器

黄山派不一定承担全部核心功能，但必须：

- 有真实产品用途的软件开发或修改；
- 参与系统联调；
- 参与最终验收。

仅烧录现成固件、把全部新增工作放到其他设备，不满足课程要求。

来源：课程指导手册第 1 页。

## 4. 课程阶段

| 阶段 | 重点 | 典型产出 |
|---|---|---|
| 第 3 周 | 熟悉课程、工具和开发板 | 环境记录、示例运行结果 |
| 第 4-5 周 | 放假 | — |
| 第 6 周 | 选题、预研、立项 | PRD 初版、风险、必达范围 |
| 第 7-10 周 | 设计、实现、测试、集成、调优 | 持续更新的代码、方案、测试、日志 |
| 第 11 周 | 功能闭环、实物验收、答辩 | 固件、源码、Git 历史、研制总结 |
| 第 12 周 | 封版归档 | 完整项目归档 |

来源：课程简介第 4 页、指导手册第 2 页。

## 5. 成绩结构

课程评分重点不是“题目看起来有多难”，而是研发过程和交付质量。

主要评价项：

- 研发过程与 Git 管理：20 分（个人）
- 阶段检查：20 分（个人）
- 技术实现与工程质量：20 分（个人）
- 产品完成度与使用体验：20 分（团队）
- 产品验收答辩：20 分（团队）

高档表现强调：

- 过程持续、清楚、可追溯；
- 重要变更有验证；
- 需求 → 设计 → 实现 → 验证链路清楚；
- 代码模块清晰；
- 测试覆盖充分；
- 产品可靠、体验良好；
- 答辩能解释、判断、修改和验证。

提交次数、代码行数、AI 生成比例、外设数量和题目等级本身不直接换算成绩。

来源：课程简介第 5-6 页、指导手册第 2-3 页。

## 6. 入门最低能力验收

需要从脚手架建立工程，并独立完成：

1. 一次可观察修改；
2. 编译；
3. 烧录；
4. 实机验证；
5. 展示对应 Git 提交；
6. 解释修改入口、运行行为和验证方法。

所以当前最优先的任务不是做 HapticPod 全部功能，而是先跑通这条最小链路。

来源：课程指导手册第 8 页。

## 7. 推荐的练习顺序

课程给出的入门练习包括：

- 环境闭环：编译、烧录、修改屏幕文字；
- 事件与状态：增加一个状态或修改转换条件；
- 后台工作：后台运行时 UI 仍能响应；
- 外设数据：接入一种已有示例的传感器；
- 停止与资源：离开功能后不继续产生陈旧结果；
- 故障与验证：制造一个可恢复错误并记录定位过程；
- Git 与交接：能定位修改前后版本，别人能按记录复现。

来源：课程指导手册第 7-8 页。

## 8. 需求怎么写

需求至少回答：

- 它是什么？
- 什么时候、怎么使用？
- 用户做什么？
- 系统反馈什么？
- 什么时候算完成？

重要需求应分为“必达”和“拓展”，并写清：

- 前置条件；
- 操作/输入；
- 可观察输出；
- 失败行为；
- 验证方式。

不要只写“实时、准确、稳定、流畅”等无法直接验证的词，应给出测量方法和目标值。

来源：课程指导手册第 8-9 页。

## 9. 方案设计至少要有三类图

- 系统架构图：模块、职责、接口；
- 数据流图：数据从哪里来、如何处理、如何传输和反馈；
- 状态机图：核心状态、事件、转换条件、错误与恢复。

来源：课程指导手册第 9-11 页。

## 10. 实现原则

课程建议：

- 先让最小流程贯通，再增加功能；
- 一次修改尽量解决一个相关问题；
- 修改前明确预期，修改后做针对性验证；
- 主线保持可构建；
- 重大实验可放分支；
- 模块接口明确输入、输出和错误；
- 不忽略失败返回值；
- 注释解释约束和理由，不逐行翻译代码。

来源：课程指导手册“6 实现与工程管理”。

## 11. AI 与开源复用

允许：

- AI 参与需求、设计、编码、测试和文档；
- 使用开源项目、库、模型和素材。

但必须：

- 能解释、修改、验证自己负责的成果；
- 记录对架构、重要实现和故障修复有影响的 AI 使用；
- 维护第三方资源清单；
- 记录来源、版本、许可和修改情况；
- 区分已有能力与自己的实现/改进/验证。

来源：课程简介第 7 页、指导手册第 4 页。

## 12. HapticPod 当前应遵循的范围原则

本项目功能较多，因此立项时应明确：

### 必达候选

- 黄山派 UI 正常运行；
- 统一输入抽象；
- 基础音乐播放闭环；
- 旋钮输入能够控制 UI；
- 至少一种可感知的可编程触觉效果；
- 基本错误状态和恢复。

### 拓展候选

- 多种触觉模式；
- 更完整音乐库信息；
- 3.5 mm 耳机输出；
- LRA 整机震动；
- PCB；
- CNC 外壳；
- 更复杂动画和功耗优化。

最终范围应在立项时根据预研结果再确认。
