# HapticPod

基于立创·黄山派的嵌入式音乐交互终端原型。

当前阶段：课程入门与技术预研。

> 本仓库按照《软件产品综合研发实践（阶段二）》课程要求维护。当前最重要的目标不是堆功能，而是先完成“修改源码 → 编译 → 烧录 → 实机验证 → Git 提交”的最小开发闭环。

## 课程技术基线

- 开发板：立创·黄山派
- 板型：`sf32lb52-lchspi-ulp`
- SiFli SDK：v2.5.1
- RTOS：RT-Thread
- GUI：LVGL v9

来源：课程指导手册第 4 页附近“平台资源与验证边界”。

## 产品设想

HapticPod 计划做成一个带 AMOLED 屏幕和可编程触觉旋钮的音乐交互终端。

核心体验设想：

- 旋转选择菜单、歌曲或音量；
- 按压确认；
- 不同界面对应不同旋钮触感；
- 菜单中有虚拟卡点，进度调节可连续旋转，边界处有虚拟限位；
- 黄山派负责 UI、音乐播放和系统逻辑；
- 独立 FOC 控制器负责无刷旋钮的高速闭环。

以上属于产品计划，最终功能以课程立项时确认的“必达范围”为准。

## 当前优先级

1. 跑通老师提供的示例/脚手架；
2. 独立完成一次可观察修改；
3. 编译、烧录并在真实黄山派上验证；
4. 把过程记录进 Git 和 `docs/development-log.md`；
5. 再逐步学习 GPIO、按键、RT-Thread 和 LVGL。

## 重要原则

- 先让最小流程贯通，再增加功能；
- 一次修改尽量只解决一个相关问题；
- 重要修改后必须验证；
- 不把“能编译”当成“产品已验证”；
- 不把第三方代码伪装成个人贡献；
- 不隐藏失败、缺陷或未验证项。
